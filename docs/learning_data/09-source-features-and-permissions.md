# 09. 자료 기능과 권한

## 먼저 생각해 보기

자료를 보는 사람과 수정하는 사람의 권한은 어디에서 구분해야 안전할까?

## 핵심 해설

SourceWiki의 중심 데이터는 `Source`다. 자료에는 URL·제목·원문·개인 메모·태그·파일·댓글이 붙는다. URL을 입력하면 tools 기능이 공개 URL 본문을 안전하게 추출하고, 작성자는 결과를 검토해 저장한다.

| 기능 | 누가 할 수 있는가 | 핵심 확인 |
| --- | --- | --- |
| 목록·상세 읽기 | 서비스가 허용한 사용자 | 공개 API 응답 형태 |
| 자료 작성 | 로그인 사용자 | access token |
| 자료 수정·삭제 | 작성자 | `source.userId`와 로그인 사용자 비교 |
| 댓글 작성 | 로그인 사용자 | 인증 + 입력 길이 |
| 파일 업로드 | 자료 작성자 | MIME·크기·소유권 |
| 좋아요 | 로그인 사용자 | 사용자/자료 복합 키 |

권한은 버튼을 숨기는 것으로 끝나지 않는다. API가 요청마다 확인해야 개발자 도구를 통한 직접 호출도 막을 수 있다.

## 이해 점검

**Q. 태그를 별도 테이블과 연결 테이블로 나누는 이유는?**  
**A.** 하나의 자료는 여러 태그를 가질 수 있고, 하나의 태그도 여러 자료에 붙을 수 있기 때문이다.

## 흔한 오해

AI 요약은 자료 본문을 자동으로 덮어쓰지 않는다. 현재는 사용자가 검토하는 보조 기능이며 운영에서는 demo 표시가 유지된다.
