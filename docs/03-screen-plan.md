# 화면 기획

## 정보 구조와 공통 UX

상단 내비게이션은 로고, 자료 목록, 자료 등록, 로그인 상태 영역으로 구성한다. 비회원은 목록·상세를 볼 수 있고 쓰기 동작을 선택하면 로그인으로 이동한다. 로그인 사용자는 닉네임과 로그아웃을 볼 수 있다.

모든 폼은 인라인 필드 오류와 상단 요약 오류를 함께 제공한다. 저장 중 버튼을 비활성화하고 중복 요청을 막는다. destructive action은 대상 제목을 포함한 확인 dialog를 사용한다. toast는 보조 피드백이며 중요한 오류는 화면에 유지한다.

## 주요 사용자 흐름

```text
가입 → 인증 메일 → 인증 완료 → 로그인 → URL 입력 → 본문 가져오기
  → 내용 검토/수정 → 자료 저장 → AI 요약 요청 → 요약 검토/수정 → 상세 공개
                                                       └→ 실패 시 수동 작성

비회원 → 자료 목록 → 상세/댓글 조회 → 작성 시도 → 로그인 → 원래 목적지 복귀
```

## 화면별 설계

### 홈/대시보드 `/`

- 서비스 한 줄 설명과 URL 중심 아카이브 예시를 제공한다.
- 최근 자료 카드와 목록 응답의 `totalItems`를 이용한 총 자료 수를 보여준다.
- 로그인 사용자에게 빠른 URL 입력과 자료 등록 CTA를 제공한다.
- 별도 통계 시스템이나 고급 분석은 만들지 않는다.

### 로그인 `/login`

- 이메일, 비밀번호, 로그인 버튼, 회원가입 링크, 인증 메일 재발송 안내를 제공한다.
- 성공 후 안전한 내부 `returnTo` 또는 자료 목록으로 이동한다.
- `EMAIL_NOT_VERIFIED`는 재발송 동작, 잘못된 자격 증명은 일반화된 메시지를 제공한다.
- 초기 `/me` 확인 중에는 로그인 폼을 잠시 표시했다가 뒤집지 않고 auth skeleton을 사용한다.

### 회원가입 `/signup`

- 이메일, 닉네임, 비밀번호, 비밀번호 확인을 받는다.
- 이메일 blur 또는 명시적 확인 버튼으로 중복 검사를 제공하지만 최종 가입 API가 다시 검증한다.
- 비밀번호 조건과 인증 메일 발송 사실을 명확히 표시한다.
- 성공 시 `/verify-email/pending?email=...`로 이동한다.

### 이메일 인증 대기·결과

- `/verify-email/pending`: 수신 주소, 재발송 cooldown, 주소 오입력 시 가입 화면 이동을 제공한다.
- `/verify-email?token=...`: 토큰을 서버에 전달해 성공·만료·사용됨·오류 상태를 표시한다.
- 성공 시 로그인 CTA, 만료 시 재발송 CTA를 제공하고 URL token은 처리 후 history에서 제거한다.

### 자료 목록 `/sources?page=1`

- 카드에는 제목, 도메인, 최대 2줄 요약/추출문, 태그, 작성자, 댓글 수, 저장일을 표시한다.
- URL의 `page`를 단일 진실 공급원으로 사용해 새로고침과 공유를 지원한다.
- 이전/다음과 현재·전체 페이지를 표시하고 결과가 없을 때 첫 자료 등록 CTA를 제공한다.
- 검색·필터는 Advanced로 표시하지 않거나 disabled UI를 만들지 않는다.

### 자료 등록 `/sources/new`

1. URL 입력 후 `본문 가져오기`를 실행한다.
2. 성공하면 제목·도메인·정제 본문 미리보기를 채우고 사용자가 검토한다.
3. 실패하면 이유와 지원 한계를 표시하되 URL과 기존 입력은 유지한다.
4. 제목, URL, 원문, 개인 메모, 태그를 수정한 뒤 저장한다.
5. 저장 성공 후 상세로 이동하고 AI 요약을 선택적으로 실행한다.

추출 전에도 제목과 URL만으로 저장할 수 있다. 페이지 이탈 시 작성 중 변경사항이 있으면 경고한다.

### 자료 상세 `/sources/[id]`

- 제목, 원본 링크, 도메인, 작성자, 날짜, 태그를 먼저 보여준다.
- AI 요약과 핵심 포인트를 본문보다 앞에 배치하고 데모 결과는 badge로 구분한다.
- 추출문은 접힌 영역으로 제공하고 원본 URL 방문을 주 동작으로 유지한다.
- 작성자에게만 수정·삭제·AI 요약 버튼을 보여주되 서버 권한 검사를 대체하지 않는다.
- 댓글 목록, 작성 폼, 작성자별 수정·삭제 메뉴를 제공한다.

### 자료 수정 `/sources/[id]/edit`

- 제목, URL, 원문, 요약, 핵심 포인트, 키워드, 태그, 메모를 수정한다.
- 권한 확인 전 편집 폼을 노출하지 않는다. 403은 목록으로 돌아갈 동작을 제공한다.
- AI 재요약은 기존 내용을 즉시 덮어쓰지 않고 미리보기 후 적용한다.

### AI 처리 상태

- 상세 내 panel에서 `요약 요청 중`, `결과 검토`, `실패`의 실제 상태만 표현한다.
- timeout·비활성·응답 형식 오류를 구분하고 다시 시도 또는 직접 작성 동작을 제공한다.
- 요청 중 페이지를 막지 않으며 사용자는 자료 상세를 계속 읽을 수 있다.

### 오류와 시스템 화면

- 404: 자료가 없거나 삭제되었음을 알리고 목록 링크를 제공한다.
- 403: 소유권이 필요한 작업임을 설명한다.
- 네트워크 오류: 입력을 유지하고 재시도한다.
- 전역 오류 boundary: 예상치 못한 렌더 오류에서 새로고침과 홈 이동을 제공한다.

## 반응형·접근성 기준

- 모바일은 1열 카드와 하단 고정 없는 주요 CTA, 태블릿 2열, 데스크톱 3열을 기본으로 한다.
- focus 순서는 시각 순서와 일치하고 modal은 focus trap과 Escape 닫기를 지원한다.
- loading skeleton은 최종 레이아웃 크기와 맞춰 layout shift를 줄인다.
- 색만으로 성공·오류·AI 데모 여부를 구분하지 않고 아이콘과 텍스트를 병행한다.
